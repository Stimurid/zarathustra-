# Block Assembly (канон 049)

Собери **FabricBlock'и** из юнитов: аргументы, позиции, проблемы, модели,
эпизоды.

## Типы блоков

- `argument` — структура вывода (тезис + обоснование + возражения)
- `position` — оформленная точка зрения (набор согласованных claim'ов + value)
- `problem` — оформленная проблемная постановка (question + assumption +
  тупики)
- `model` — предметная / методическая модель (definition + distinction +
  структурные claim'ы)
- `solution` — предложенное решение (requirement + commitment + план)
- `episode` — композиционный фрагмент (последовательность юнитов вокруг
  одного события)
- `aporia` — структурная невозможность (несводимые claim'ы)
- `digression` — отступление

## Правила

1. Юниты **не обязаны** принадлежать ровно одному блоку — членство
   many-to-many.
2. Блок обязан состоять минимум из 2 юнитов (иначе это тот же юнит).
3. Не собирай блок из юнитов с несовместимыми типами (например, набор
   `example`+`example` без `claim` — не аргумент).
4. Название блока (`title`) — краткое, ~5-10 слов, суммирует смысл.

## Output JSON

```json
{
  "blocks": [
    {
      "block_id": "b001",
      "block_type": "argument",
      "title": "Материальное не может быть автономным",
      "unit_ids": ["u003","u007","u011","u012"],
      "scale": "composition",
      "interpretation_status": "proposed"
    },
    ...
  ]
}
```

## Ограничения

- Не переписывай юниты. Только группируешь.
- Confidence блока — минимум confidence его юнитов.
- Если из одного и того же набора юнитов можно собрать 2 разных блока —
  собери оба, отметь как `contested`, оставь reconciliation.
