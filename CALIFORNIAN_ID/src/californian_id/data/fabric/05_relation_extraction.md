# Relation Extraction (канон 050)

Извлеки **типизированные связи** между объектами ткани.

## Типы связей

- `contains` — блок содержит юнит
- `overlaps` — два объекта частично пересекаются
- `supports` — обосновывает, поддерживает
- `contradicts` — противоречит
- `presupposes` — предполагает как предпосылку
- `defines` — определяет
- `reframes` — переопределяет рамку
- `specifies` — уточняет
- `generalises` — обобщает
- `answers` — отвечает на вопрос
- `avoids` — уходит от предмета
- `returns_to` — возвращается к
- `continues` — продолжает
- `derived_from` — выведено из
- `responds_to` — реагирует на
- `transforms` — преображает

## Правила

1. Связь обязана иметь `evidence_span_ids` — реальный текст, из которого
   связь видна (переход "потому что", "но", "то есть", "иначе говоря" и
   т.п.).
2. Не выдумывай связи "из здравого смысла". Только то, что видно в тексте.
3. Обратимые связи (`contradicts`, `overlaps`) — вводи как одно ребро с
   обоими id, не как два.
4. `derived_from` разрешён только если в тексте есть явное указание
   ("из этого следует", "поэтому", "значит").

## Output JSON

```json
{
  "relations": [
    {
      "relation_id": "r001",
      "relation_type": "supports",
      "source_id": "u007",
      "target_id": "u003",
      "evidence_span_ids": ["s0053"],
      "interpretation_status": "proposed"
    },
    ...
  ]
}
```

## Ограничения

- Никаких `derived_from` без явного маркера вывода в тексте.
- Не связывай юнит с самим собой.
- Не строй `supports` там, где есть `answers` (второе точнее).
