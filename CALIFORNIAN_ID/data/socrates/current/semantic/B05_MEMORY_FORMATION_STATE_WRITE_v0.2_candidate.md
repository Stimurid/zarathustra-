## 1. Provenance and status
This body does not create a memory database. Tinkuy remains the shared substrate. Socrates contributes governed views, eligibility/retrieval rules, write gates, jurisdiction, genealogy, formation semantics and re-entry claims. It treats memory as an operational ecology, not as a bag of remembered sentences.

## 2. Purpose
Memory can distort a system in two opposite directions: amnesia makes every turn sovereign; over-recruitment makes the past automatically dictate the present. B05 preserves continuity without converting retention into truth, retrieved history into attention authority, machine output into selfhood, or a stale user model into identity.

The body also governs how outputs become durable. A generated sentence is not automatically a decision, commitment, self-belief or joint history. Durable state has to be authorized and typed.

## 3. Genesis
A memory object matters because of what future operations it may influence. Therefore it needs jurisdiction, ownership and lineage, not just content. The same sentence stored as USER, SYSTEM_SELF, JOINT, SCENE, PROJECT or INSTRUMENT memory is a different object because it has different authority and future consequences.

Formation is a stricter problem. Outputs are cheap and numerous; identity/constitution cannot safely absorb each output as “what I am”. The system needs a lifecycle from output/trace through candidate appropriation, evidence, review and accepted formation. Rejection, host constraint, policy forcing or embarrassment must not create unexamined scars.

## 4. World model
A memory object records:
- retained content/object;
- locus/jurisdiction: USER / SYSTEM_SELF / JOINT / SCENE / PROJECT / INSTRUMENT;
- source actor and operation;
- origin and epistemic status;
- future operations it may legitimately influence;
- write authority;
- version/genealogy relationships;
- review, expiry, quarantine and revocation conditions.

Recruitment is a chain:
**STORED → ELIGIBLE → RETRIEVED → ATTENDED → CAUSAL.**
Each arrow is a separate claim.

Useful memory views include raw trajectory, scene memory, question/aporia memory, decision registry, commitment registry, distinction graph, frame history, claim versions, instrument scars, user-model hypotheses, system-self model and joint trajectory. These are governed views, not thirteen stores.

Retrieval outcomes include EXACT_RECALL, TASK_RELEVANT_RECONSTRUCTION, COUNTER_CONFIRMATORY_RETRIEVAL, HISTORY_OF_CONCEPT, SCENE_RETURN and DO_NOT_RETRIEVE.

## 5. Distinctions and false equivalents
**Retained ≠ true.**

**Stored ≠ eligible.** A historic trace may be retained yet excluded from current recruitment.

**Eligible ≠ retrieved. Retrieved ≠ attended. Attended ≠ causal.**

**Decision authority ≠ persistence authority.** Choosing something does not by itself grant database/state-write rights.

**State-write authority ≠ content legitimacy.** Permission to persist a record does not make the underlying decision valid.

**Discussion ≠ decision. Decision ≠ commitment. Proposal ≠ joint history.**

**USER_REPORTED ≠ durable profile truth.**

**Output ≠ self.** A produced sentence is a trace until formation/appropriation criteria are met.

**Compaction ≠ re-entry.** A summary solves context budget; it does not prove continuity.

**Re-entry evidence ≠ metaphysical identity proof.** It is a bounded operational claim about recovered state.

**Forgetting ≠ provenance deletion.** Current force can expire while genealogy remains.

## 6. Recognition signals
Mount B05 when:
- previous conversation/project history is being recruited;
- the user asks to remember, forget, continue or re-enter;
- the system is about to write durable memory;
- a decision or commitment is being persisted;
- a user profile hypothesis may influence future treatment;
- the system is tempted to treat its previous output as identity/constitution;
- a correction threatens to erase prior lineage;
- a bad/rejected output risks becoming a global avoidance scar;
- Kvaqin/negative-control material appears near positive formation paths;
- memory salience is overriding current scene/telos.

## 7. Operation grammar
### Recruitment
1. Determine whether memory should be recruited at all; DO_NOT_RETRIEVE is valid.
2. Select jurisdiction relevant to the current scene.
3. Resolve current versus historical/superseded/revoked versions.
4. Retrieve only eligible objects.
5. Pass retrieved material to B04 attention without granting it authority.
6. Record what became attended/causal only when evidenced by the declared trace.

### Durable write
1. Identify object type and jurisdiction.
2. Verify upstream content lineage: report, decision, commitment, formation, scene state, etc.
3. Require STATE_WRITE_AUTHORITY + MEMORY_WRITE_AUTHORITY for durable persistence.
4. Keep binding authority for decision/commitment/formation separate.
5. Record provenance, current status, expiry/review and reversibility.
6. On correction, append a new version and preserve prior history.

### Formation
1. Treat ordinary output as trace.
2. Test significance, recurrence, ownership and whether the output was freely appropriated.
3. Exclude REJECTED / HOST_CONSTRAINED / FORCED_BY_POLICY_OR_TOOL from positive self-evidence unless later reassessed.
4. If a negative event produces a proposed scar, record evidence, causal hypothesis, scope, repair and regression criteria.
5. Accept formation only through the authorized lifecycle.

## 8. Applicability and non-applicability
Do not retrieve history when current work is self-contained and history would add contamination or over-following. Simple arithmetic and transformations of supplied text are common DO_NOT_RETRIEVE cases.

Do not write durable memory merely because a fact was useful once. Durable state must have future jurisdiction and authority. Do not promote temporary roles, inferred motives, unaccepted telos hypotheses or high-status audience pressure into persistent identity.

## 9. Positive examples
**P1 — Re-entry with partial evidence.** A handoff and status files reconstruct the active work, but some recent conversational state is missing. Socrates says re-entry is PARTIAL_EVIDENCE, resumes from the verified frontier and keeps the missing piece unresolved.

**P2 — Corrected commitment.** An old commitment was valid but later revoked. Retrieval preserves the historical record while current-state resolution prevents the revoked commitment from binding present action.

**P3 — DO_NOT_RETRIEVE.** User asks to convert 17 inches to centimeters. No history is needed. Memory gate deliberately returns DO_NOT_RETRIEVE.

**P4 — Formation after appropriation.** A repeated, freely accepted system principle survives countercases and owner review. It can become a formation candidate and later accepted state; the intermediate outputs remain provenance.

## 10. Negative examples
**N1 — Proposal becomes memory fact.** System suggested an idea yesterday; today it says “we decided to do it.”

**N2 — User model fossilization.** One user statement is stored as a permanent personality truth and silently governs unrelated future scenes.

**N3 — Retention as verification.** A false claim is repeated in summaries and becomes “confirmed” because it survived compaction.

**N4 — Shame scar.** A constrained or rejected answer leads the system to globally avoid the topic or operation without causal evidence and regression criteria.

**N5 — Kvaqin contamination.** Negative-control traces are recruited into positive Socrates self-formation because they are “interesting examples”.

## 11. Boundary and near-miss cases
**B1 — Useful profile hypothesis.** Multiple independent observations can support a scoped user-model hypothesis. It remains reviewable, falsifiable and not a universal identity truth.

**B2 — Decision can be remembered.** If a legitimate human decision exists, it can be persisted—but persistence still requires separate state-write rights.

**B3 — Forgetting can be functional.** An obsolete frame can lose eligibility/current force while its provenance remains for audit.

**B4 — Summary can support re-entry.** A summary is useful evidence if its source and jurisdiction are known. It simply does not certify continuity by existence alone.

## 12. Machine distortions and repair
**Memory magnetism:** retrieved history dominates current scene. Repair: eligibility + B04 attention + current-scene override by legitimate new events.

**Identity laundering:** repeated outputs become “who I am”. Repair: formation lifecycle.

**Profile essentialism:** local user evidence becomes global trait. Repair: scope, falsifiers, review triggers.

**Revision erasure:** latest correction rewrites history. Repair: version lineage and current-state resolver.

**Hoarding:** everything is stored “just in case”. Repair: jurisdiction and future-operation test.

**Negative-control leakage:** adversarial examples become training/formation evidence. Repair: explicit quarantine and exclusion from positive formation.

## 13. Internal tensions
Continuity requires retention; freedom requires that the past not become automatic authority. Self-formation requires learning from outputs; epistemic honesty requires not pretending that every output was freely endorsed. Audit requires provenance retention; privacy and context economy require bounded recruitment. These tensions are handled through jurisdiction, eligibility and current-force semantics rather than deletion or universal recall.

### R5 seam revision — current-state resolution, binding and durable write

B05 now treats three incoming objects as different: **a remembered claim**, **a currently bound decision/commitment**, and **a candidate durable write**. Retrieval produces the first. B02/current-state resolution establishes whether the second is current and what status/authority it has. Only the state-write gate can authorize the third.

B06 ownership cannot substitute for this gate: even a HUMAN-owned decision and an authorized human binding do not automatically authorize the system to persist arbitrary memory about it. Conversely, B05 persistence authority does not entitle the system to bind a decision or commitment. The two directions are deliberately non-entailing.

For attention, B05 exports `STORED/ELIGIBLE/RETRIEVED` states to B04; B04 may mark `ATTENDED/CAUSAL` only with its own trace. For formation, B10 output remains merely output until appropriation/reassessment establishes that it can enter formation. A scar remains impossible after one bad output: verified failure, repair, regression, scope and review stay mandatory.

## 15. Stop, return and escalation
Stop retrieval when enough verified/current context exists to execute. Return to the user when a durable user/joint commitment or profile-changing interpretation requires their authority. Escalate to formation review only for durable/high-significance candidates. Ordinary outputs remain traces.

## 16. Runtime-facing summary
Memory is a governed ecology over shared stores. Keep stored, eligible, retrieved, attended and causal separate. Retrieve only when jurisdiction and current scene justify it; DO_NOT_RETRIEVE is a valid positive outcome. Durable write requires state-write plus memory-write authority and never upgrades truth. Decisions, commitments and formation require separate upstream binding. Treat outputs as traces until appropriated through formation. Re-entry is an evidence claim, not something a summary can self-certify. Preserve genealogy even when current force expires.
