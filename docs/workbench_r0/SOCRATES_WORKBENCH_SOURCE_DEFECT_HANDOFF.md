## SD-001 — набор схем не совпадает с контрольным манифестом

**Серьёзность:** средняя (расхождение состава поколения)
**Свидетельство:** `G-S24_SHA256SUMS` (`1p-a9C5kiRsYQRrGurK6_GhaDrmBbed_y`,
37 записей) против девяти предоставленных id схем.

Из девяти схем в контрольном манифесте владельца присутствует **одна**:

| Схема | В манифесте G-S24 |
|---|---|
| `pipeline_trace.schema.json` | **да** (`cc3e740f…bbcbea`) |
| `intervention_selection.schema.json` | нет |
| `arbitration_record.schema.json` | нет |
| `council_recipe.schema.json` | нет |
| `human_operation.schema.json` | нет |
| `human_operation_return.schema.json` | нет |
| `ownership_assessment_v0.2.schema.json` | нет |
| `competence_after_interaction.schema.json` | нет |
| `development_risk.schema.json` | нет |

**Почему это важно.** Восемь схем — это контракты входа/выхода S6, S7 и S8,
то есть человеческого шлюза, арбитража и выбора вмешательства. Если они не
входят в G-S24, то поколение объявляет шаги, чьи контракты принадлежат другому
(или ещё не зафиксированному) поколению; если входят — контрольный манифест
неполон и не может использоваться как проверка целостности.

**Что мы сделали:** пометили каждую как `in_owner_manifest: false` и
`readiness: CONTRACT_READY / NOT_IN_G-S24_MANIFEST`; они видны в
контракт-инспекторе.

**Что нужно от владельца:** решить, какая из двух версий верна — расширить
`G-S24_SHA256SUMS` или переназначить схемы другому поколению.

## SD-002 — тело промпт-пака отсутствует в контрольном манифесте

**Серьёзность:** средняя (провенанс не проверяем)
**Файл:** `prompts/MODE_AND_REFLEXIVITY_GOVERNOR_PROMPT_PACK.md`
(`1FRmTQfj2Vxwmgde_C_u2zX1fbGISGLUL`, 1844 B, изменён 2026-08-15)

`prompt_bindings_v0.3.yaml` (G-S24) объявляет этот файл телом промпта для
S7–S8. Самого файла в `G-S24_SHA256SUMS` нет.

Дополнительно: **заголовок файла говорит `G-S23`**, тогда как связывающий его
файл — G-S24.

**Последствие для нас:** мы не можем заявить `BYTE_EXACT` — сверять хеш не с
чем. Файл втянут как `BYTE_EXACT_UNVERIFIED` (размер сверен с метаданными
Drive, четыре содержательных якоря сверены с двумя независимыми чтениями).

**Что нужно от владельца:** внести файл в контрольный манифест поколения,
которому он принадлежит, и привести заголовок в соответствие.

## SD-003 — тела контрактов шагов недостижимы, папка не перечисляется

**Серьёзность:** высокая для дальнейшей интеграции
**Папка:** `1nlNWyA3wkdq54qwBRB9GPd13P07-lttU`

`G-S24_SHA256SUMS` содержит имена и sha256 всех 11 контрактов шагов
(`steps/S0_intake_and_context_jurisdiction.yaml` … `steps/S10_…yaml`), но:

* прямые file id не предоставлены;
* перечисление содержимого папки для этого аккаунта возвращает пустой
  результат (`EMPTY_FOR_THIS_ACCOUNT`).

**Формулировка намеренно осторожная:** это **не** «папка пуста». Ровно та же
картина ранее наблюдалась для всего пакета, и она оказалась ложноотрицательной —
пакет существовал, а перечисление его не показывало.

**Последствие:** контракты шагов известны по хешу, но не по содержанию.
Полная проверка контрактов S0–S10 невозможна до предоставления прямых id.

**Что нужно от владельца:** выдать прямые file id 11 контрактов шагов
(или доступ, при котором перечисление работает).
